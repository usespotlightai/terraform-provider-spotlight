# spotlight_workspace (Resource)

A Spotlight workspace. A person creates it by signing up in the web app; Terraform adopts it with an `import` block that names its slug, then manages everything inside it.

Creating a workspace from Terraform needs a caller allowed to create workspaces, and API tokens are not: a token acts only inside its own workspace. Import the workspace rather than creating it.

## Adopt a workspace

A workspace is created by a person signing up in the web app. Bring it under Terraform with an `import` block that names its slug, next to a `spotlight_workspace` whose `name` and `slug` match what is there, so the first plan imports it and changes nothing. Terraform then manages everything inside it: its teams, lines, skills, integrations and harness profiles, its secrets, and its runner pools and trusts.

```terraform
import {
  to = spotlight_workspace.acme
  id = "acme"
}

resource "spotlight_workspace" "acme" {
  name = "Acme"
  slug = "acme"
}
```

## Limit the hosts Spotlight calls

`outbound_hosts` limits the hosts that Spotlight calls for the workspace's configuration: its integrations, hooks and MCP servers, their OAuth servers, the provision URLs of its runner pools, and the issuers of its OIDC trusts. Spotlight calls a host only when the deployment and the workspace both allow it. An empty set narrows nothing, so the deployment's allowed hosts apply alone. A change applies to calls in at most 30 seconds.

Each entry is an exact host, as in `api.linear.app`, or a pattern, as in `*.acme.io`, which matches every host below `acme.io` but not `acme.io` itself. Write the hosts in lower case, without a trailing dot, and with no scheme, port or path. Write an internationalised host in its `xn--` form. `*` alone is refused: to permit every host, leave the set empty.

```terraform
resource "spotlight_workspace" "acme" {
  name           = "Acme"
  slug           = "acme"
  outbound_hosts = ["*.acme.io", "api.linear.app"]
}
```

## Creating a workspace

Creating a workspace from Terraform needs a caller allowed to create workspaces. API tokens are not: a token acts only inside its own workspace, and creating one fails with `403 Forbidden`. The provider reports that error with the `import` block to write instead.

## Stop managing a workspace

Destroying a `spotlight_workspace` requests that Spotlight delete the workspace. To stop managing it without deleting it, replace the resource with a `removed` block (Terraform 1.7 or later):

```terraform
removed {
  from = spotlight_workspace.acme

  lifecycle {
    destroy = false
  }
}
```

## Schema

### Required

- `name` (String) What the workspace is called.
- `slug` (String) Where the workspace lives in the web app. It is immutable, so changing it replaces the workspace.

### Optional

- `outbound_hosts` (Set of String) The hosts Spotlight may call for the workspace's configuration, as exact hosts, as in `api.example.com`, or patterns, as in `*.example.com`. Write them in lower case, without a trailing dot, and with no scheme, port or path. The deployment must allow a host too. An empty set narrows nothing. A change applies to calls in at most 30 seconds.

### Read-Only

- `address` (String) Names the resource within its workspace, as in `acme`.
- `id` (String) Issued by Spotlight when the workspace is created, and never changed.
- `version` (Number) Rises with every change to the workspace; each write sends it back so a change made since is not overwritten.

## Import

In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import) with the workspace's slug as the `id`:

```terraform
import {
  to = spotlight_workspace.acme
  id = "acme"
}
```

In Terraform v1.12.0 and later, the `import` block can name the workspace by its identity, the id Spotlight issued it, instead:

```terraform
import {
  to = spotlight_workspace.acme
  identity = {
    id = "5b1e9d2c-7a43-4f8e-b6c0-3d9a8e1f2b57"
  }
}
```
